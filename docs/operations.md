# 운영 노트 — 외부 공용 API 사용 정책 · 프록시 · 한계

이 문서는 Midpoint 가 쓰는 **공용 API 세 곳**(Nominatim · Photon · Overpass/OSM 지도 API)의
사용 정책, 지금 코드가 실제로 지키는 범위, 그리고 **아직 구축하지 못한 것**을 구분해 적는다.
"운영 준비 완료"라는 표현은 이 문서 어디에도 해당하지 않는다 — 서버 프록시는 미구축이다.

## 1. 사용하는 공용 API

| API | 쓰는 곳 | 호출 빈도 (클라이언트) | 대체 경로 |
| --- | --- | --- | --- |
| Nominatim (`nominatim.openstreetmap.org`) | 참가자 좌표 역주소 · 주소 검색 | 앱 전체가 **하나의 큐**로 1.1초 간격 (초당 1건 이하) | Photon |
| Photon (`photon.komoot.io`) | Nominatim 429·5xx·타임아웃·0건일 때, 쿨다운 중 주 제공자 | 같은 큐 (1.1초 간격) | 없음 (둘 다 실패 → 화면 안내) |
| Overpass 미러 4곳 (`overpass-api.de`, `lz4`, `kumi`, `private.coffee`) | 중간 지점 반경 1~3km 맛집·카페 | 0ms · 1.2s · 2.5s · 5.2s 시차 출발, 먼저 답한 쪽 채택 | OSM 지도 API |
| OSM 지도 API (`api.openstreetmap.org/api/0.6/map.json`) | Overpass 가 밀릴 때 후퇴로 | 3.6초 뒤 출발 | 없음 |

앱은 정적 GitHub Pages 파일만으로 동작한다. 서버·빌드 단계는 없다(지도 키 하나 제외).

## 2. 코드가 지키는 요청량 규칙

- **한 큐**: 역주소(참가자 수만큼)와 주소 검색이 같은 레이트 리미터를 쓴다. 기본 간격
  1.1초(`GEOCODE_MIN_INTERVAL_MS`).
- **사용자 검색 우선**: 주소 검색은 `priority: 'high'` 로 큐에 들어가, 아직 시작하지 않은
  역주소 요청을 건너뛰고 먼저 나간다. 참가자 12명을 등록하는 중에 새 주소를 검색해도
  역주소 12건(≈13초)을 기다리지 않는다. 진행 중인 요청은 끊지 않는다.
- **불필요해진 역주소 취소**: 참가자를 지우거나 다른 자리로 끌면 그 좌표의 역주소를
  큐에서 빼거나 `AbortController` 로 끊는다(`cancelReverse`, 앱의 `cancelAddress`).
- **중복 병합(in-flight)**: 같은 질의·같은 좌표가 동시에 들어오면 요청 하나를 함께 쓴다.
- **캐시**: 검색 30분, 0건 2분, 역주소 30분(메모리) + 브라우저 7일(`pkp2.geo.v1`).
  같은 질의·좌표는 네트워크를 다시 쓰지 않는다.
- **429 처리**: 재시도하지 않고 즉시 Photon 으로 넘긴다. `Retry-After` 는 Nominatim 재사용
  제한 시각으로 삼아(쿨다운 기본 60초 · 연속 2배 · 최대 10분, `Retry-After` 가 더 길면 그 값)
  그동안은 Photon 을 먼저 쓴다. 주 제공자가 정상 응답하면 연속 실패 횟수를 0으로 되돌린다.
- **5xx 만 재시도**: 1회, 대기는 최대 10초로 자른다.
- **실시간 POI**: 세션·브라우저 저장소 캐시 30분(반경을 덮을 때만 재사용). 0건 응답 하나로
  전체 조회를 끝내지 않고 다른 요청의 유효한 응답을 잠시(2.5초, 최대 6초) 더 모은다.

## 3. 실패 시 대체 경로

| 상황 | 앱이 하는 일 | 화면 |
| --- | --- | --- |
| Nominatim 429 / 5xx / 타임아웃 | Photon 검색·역주소 | 결과는 정상 표시, `stats.fallbacks` 증가 |
| Nominatim 200 + 결과 없음 | Photon 에도 질의해 합친다 | 결과 없으면 "지도에서 직접 찍어 보세요" |
| Photon 도 실패 | `GeocodeError` (`search_unavailable` / `rate_limited` / `timeout`) | 원인별 안내 문구, 앱은 계속 동작 |
| 역주소 둘 다 실패 | `{ text: '', error }` — 예외 없음 | 참가자 줄에 좌표만 표시 |
| Overpass 전부 실패 | `LivePlacesError` | 내장 스냅샷 POI 유지 + "조회 실패" 안내 |
| POI 0곳 | 빈 목록 | "실시간 0곳" (실패와 구분) |

## 4. 서버 프록시 훅 (코드 준비 완료 · 서버 미구축)

`js/geocode.js` 는 엔드포인트를 한 곳에서 만든다.

```js
// index.html 에서 모듈보다 먼저
globalThis.HD2_GEOCODE_PROXY = 'https://<host>/midpoint/geo';
```

또는 `createGeocoder({ proxyUrl })`. 규약은 다음과 같다.

| 프록시 경로 | 원본 |
| --- | --- |
| `{base}/nominatim/search?…` | `https://nominatim.openstreetmap.org/search?…` |
| `{base}/nominatim/reverse?…` | `https://nominatim.openstreetmap.org/reverse?…` |
| `{base}/photon/api?…` | `https://photon.komoot.io/api/?…` |
| `{base}/photon/reverse?…` | `https://photon.komoot.io/reverse?…` |

프록시가 전역 레이트 리미터·사용자별 쿼터·캐시를 대신 지키면, 클라이언트 큐는 그대로 두고
트래픽만 서버로 옮길 수 있다. **프록시 서버는 아직 배포하지 않았다.** 따라서 지금 배포본은
방문자마다 공용 API 를 직접 호출한다.

## 5. 사용자 간 공유 캐시 (검토 결과 · 미구현)

- 캐시 키는 **정규화한 질의 문자열**과 **6자리 좌표 키**다. 둘 다 개인정보가 아니므로
  서버 캐시로 공유해도 된다: 같은 "강남역" 검색과 같은 좌표 역주소는 사용자끼리 재사용 가능.
- 개인과 연결되는 것은 **어떤 좌표를 물었는가**뿐이다. 공유 캐시에는 질의·좌표·응답만
  저장하고 IP·세션·사용자 식별자는 저장하지 않는 것을 전제로 한다.
- TTL 은 클라이언트와 같게(검색 30분 · 0건 2분 · 역주소 30분) 두고, 0건은 공유하지 않는 편이
  안전하다(지도 데이터는 수시로 바뀐다).
- 결론: **설계상 가능하지만 서버가 없으므로 구현·검증하지 않았다.**

## 6. 다중 사용자 운영 준비 상태 — 정직한 구분

| 항목 | 상태 |
| --- | --- |
| 클라이언트 요청량 제어(1.1초 큐 · 검색 우선 · 취소 · 병합 · 캐시) | **구현·테스트 완료** |
| 429 즉시 대체 · Retry-After 쿨다운 · 복구 시 초기화 | **구현·테스트 완료** |
| 프록시 전환 훅(경로 규약 · 주입 지점) | **코드 준비 완료** |
| 서버 프록시(전역 쿼터 · 공유 캐시 · IP 단위 제한) | **미구축** |
| 프록시 없이 다중 사용자 트래픽을 감당하는 것 | **보장하지 않음** — 방문자 수만큼 공용 API 를 직접 부른다 |
| Overpass 미러 부하 분산 | 미러 4곳 시차 시도(클라이언트)까지. 서버 측 큐 없음 |

즉 지금 상태는 "개인·소규모 사용에서 공용 API 예절을 지키는 정적 앱"이고, "여러 사용자가
몰려도 안전한 운영"은 프록시가 배포된 뒤에 판정할 수 있다.
